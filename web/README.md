# web/ —— 网页工作台（把「栈」摆出来看）

一个**不需要记词名**的前端原型：词表在左边，栈在中间，函数帧在右边，拖来拖去就把程序拼出来。
它只跟 `ravel --serve` 打交道，不解释方言、不自己求值。

```sh
make all            # 先有 bin/ravel
make web-mock       # 离线：RB_LLM=mock，页面在 http://127.0.0.1:8787/
# 或者接真的 provider（读 ~/.config/ravel/config.json / 环境变量）
make web
```

```
python3 web/bridge.py --mock --port 8787 --no-config --allow-shell false
```

## 三条不变量（先看这个再改代码）

1. **前端不解析、不求值**（`docs/FRONTEND.md` / REQ-24）。`app.js` 只做字符串拼接；
   `result.stack` 里的每一项都是**后端渲染好的文本**，前端原样显示，不当表达式读。
2. **两套栈是两件事**：
   - **本地栈**（`state.stack`）：你摆出来的字面量，还没发出去，随便改序 / 编辑 / 分割；
   - **后端栈**（`state.last.stack`）：上一次 `eval` 之后后端的真实栈，只能"拖回"（复制一项文本）。
     它是**跨请求保留**的（REQ-42 / REPL 语义），所以反复运行会累积——想干净重来勾「干净栈」
     （运行前发一条 `reset`）。
3. **拖动只改本地**：`dragstart` 里绝不重建 DOM（只补 `is-sel` 类），否则 drop 目标会脱离文档。

## 手势与按键

| 想做的事 | 怎么做 |
| --- | --- |
| 压一个值 | 上面输入框 + 回车（或「压入」） |
| 找词 | 左边搜索：先按**名字**精确命中，再退回名字/栈效应/说明的包含匹配 |
| 开一帧 | **点一个词**（有选中项时，选中的项就是参数），或把词拖到右栏 |
| 给帧加参数 | 把栈项拖进帧的「参数」区；把帧里的参数拖回栈 = 移出 |
| 改顺序 | 拖栈项：落点在卡片**上半**=插到它前面，**下半**=插到它后面 |
| 多选 | 点第一项，`Shift`/`⌘`/`Ctrl` 点其余；点卡片左侧的 ⋮ 手柄也是累加选择 |
| 单项动作 | 卡片右侧：`✎` 编辑（也可以双击）、`✂` 分割、`⧉` 复制、`✕` 删除 |
| 批量动作 | 选中后出现工具条：开帧… / 包成引号 / 复制 / 删除 / 取消 |
| 返回 | 帧上「⟵ 返回」= 把整帧结果按栈序压回主栈；拖某一项结果回栈 = 只返回那一项 |
| 丢弃 / 归还 | 「↩ 归还」把参数原样回栈；`✕` 丢弃整帧 |
| 跑 | `▶ 运行` 或 `Ctrl/⌘+Enter`（源默认由栈推导；勾「手改」后可自己写） |
| 主题 | 顶栏「主题」循环 `dusk` / `paper` / `neon`（记在 `localStorage`） |

选中项开帧后，参数按**书写序**排列——即方言里最左的实参是栈顶。`源：` 那行就是即将发出去的文本。

## 文件

| 文件 | 干什么 |
| --- | --- |
| `index.html` | 三栏骨架：词表 / 工作台 / 函数栈 + 底栏。**没有逻辑**。 |
| `app.css` | 三层：① 设计令牌 + 四套皮肤（`:root` 与 `[data-theme]`）；② 骨架与断点；③ 组件 |
| `app.js` | 全部交互（原生 DOM，无框架、无构建步骤） |
| `bridge.py` | 桥：一个 `ravel --serve` 子进程 ↔ HTTP + SSE；纯标准库 |
| `gen-catalog.py` | 从规格附录 A 机械抽取词表 → `words.json`（不手写，防漂移） |
| `words.json` | 生成的词表（142 词 / 15 层），`arity` 由栈效应的 `--` 左侧推出 |

### 桥的接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/eval` `{"src":…}` | → `result`（`ok` / `stack` / `code` / `error`） |
| `POST` | `/api/reset` `/api/cancel` `/api/ping` `/api/hello` | 直通协议同名请求 |
| `GET` | `/api/events` | **SSE**：`chunk` / `event` / `close` / `stderr` / `backend-exit` 原样推 |
| `GET` | `/api/words` `/api/log` | 词表 / 后端 stderr 尾巴 |

配对规则照协议 v1：`result` 回显 `id`；`hello`/`pong`/`bye` 不回显，只能按 `type` 配对。

## 加一套皮肤

`app.css` 里复制一段 `[data-theme="名字"] { … }`，填这些令牌：
`--paper*`（底）、`--ink*`（字）、`--line*`（线）、`--accent*`、`--ok/--warn/--bad`、
`--art-orb-a/b`、`--art-grid`。再把名字加进 `app.js` 的 `THEMES` 数组。
`@media (prefers-reduced-motion)` 已经把所有 `--dur-*` 归零。

## 已知边界

- **后端栈会累积**（REPL 语义）。工作台的本地栈才是"我这次的输入"。
- 帧的「返回」把**整帧结果**压回主栈；想只拿一项就拖那一项。
- 词表的 `arity` 只是提示：参数给少了后端会报 `20`（栈下溢），照常显示 `code` 与错误文本。
- 页面不存历史，刷新即清空（后端工作区仍在，因为桥没重启）。
- 桥只监听 `127.0.0.1`；要给别人看得自己加 `--host`（没有鉴权，别往公网放）。
