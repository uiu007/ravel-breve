## SF-01 `3 3 =` 与 REQ-01 镜像规则矛盾（**缺陷**，CHK-1）

- **位置**：REQ-05 验收标准（「`3 3 =` 得 `true`」）。
- **现象**：REQ-01 规定一行内**从右向左**求值。`3 3 =` 的最右 token 是 `=`，
  按镜像规则它**最先**执行 → 此时栈为空 → 必然栈下溢（退出码 30），不可能得 `true`。
  正确写法是 **`= 3 3`**。
- **佐证**：规格自身的修订表（附录 E 第 1 行）已把 `double : [ 2 * ]` 改为 `[ * 2 ]`，
  即承认「镜像后语义必须成立」；REQ-05 的这处示例是同一类问题的遗漏。
- **建议**：把 REQ-05 验收标准改为「`= 3 3` 得 `true`；`3 3 =` 为栈下溢（反例）」。
- **实现现状**：实现按镜像规则执行（`= 3 3` → `true`；`3 3 =` → 30），
  并在 `tests/conformance/req-01-notation.janet` 里把「后缀写法不成立」写成**正面验收**。
- **裁决**：CHK-1。**v1.0c 处置**：已修正（REQ-05 + §4.9.1）。

## SF-02 REQ-31 的转译产物示例是宿主相关的（**留白**，CHK-1）

- **位置**：REQ-31 示例 `(do (rb/push "abcde") (rb/push 2) (rb/take))`。
- **现象**：该文本形式隐含了宿主是 Janet（S 表达式 + `rb/` 前缀）。
  规格正文并未规定「产物必须是宿主可读文本」——只说「可 dump」。
- **实现现状**：实现**逐字**产出上述文本（`--dump` 直接打印），使该示例成为可回归的验收。
- **建议**：在 REQ-31 补一句「产物形态由宿主决定；本规格以 Janet 为例」，以免换宿时该示例失效。
- **裁决**：CHK-1。**v1.0c 处置**：已在 §4.9.2 补上该措辞。

## SF-07 块内换行的语义未规定（**留白**，CHK-1）

- **现象**：REQ-03（块内同样 RTL）与 REQ-04（换行终结语句）在**多行块**上如何组合，规格未给例。
  两种解释：
  (a) 块内换行 = 语句分隔，逐语句反转、语句间保持书写序（**本实现采用**）；
  (b) 整块视为一条语句，整体反转（会把多行块的书写序倒置）。
- **建议**：在 §4.9 补一个多行块示例钉死解释。
- **裁决**：CHK-1。**v1.0c 处置**：已冻结为 REQ-40（含多行块示例）。

## SF-08 比较运算的实参次序未规定（**留白**，CHK-1）

- **现象**：`- 5 3` 有明确直觉（5 减 3），但 `< 5 3`、`at 0 "abc"` 等的左右语义未给例。
- **实现现状**：统一为「最左实参 = 栈顶 = 先消费」（D-04），即 `< 5 3` → `false`。
- **裁决**：CHK-1。**v1.0c 处置**：已由 §4.9.1 的推论**唯一导出**，不再单列规则。

## SF-09 定义行在 `--serve` 下的生命周期未规定（**留白**，CHK-5）

- **现象**：REQ-30 要求并发求值互不污染**栈**；但未说定义（字典）是否跨请求保留。
- **实现现状**：栈默认逐请求隔离（前端策略）、工作区状态全局（D-06）。
- **裁决**：CHK-5。**v1.0c 处置**：已冻结为 REQ-30/42/45/46——“栈 vs 字典”不是两条生命周期，而是“**临时值 vs 工作区状态**”的二分；唯一持久状态 = 工作区（agent store + 字典）；并发在流层。
