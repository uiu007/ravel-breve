# NDJSON over stdio 协议（草案，待 CHK-5 冻结）

REQ-24：编辑器 = 前端（只渲染与输入），`ravel breve` = 后端（唯一求值者），以 **NDJSON over stdio** 通信。
本文是 M0 骨架已经实现的**最小子集**；M5 扩展为完整协议后冻结。

## 传输

- 一行一条 JSON，`\n` 结尾，UTF-8。
- 后端 stdout **只输出**协议消息；日志/诊断走 stderr。
- 输入 EOF（stdin 关闭）→ 后端退出码 0。
- 空行（只含空白）**忽略**，不产生响应。

## 请求（前端 → 后端）

M0 只支持一种请求：**一行 ravel 源码**（裸文本，不是 JSON）。

```
take 2 "abcde"
```

> 为何裸文本：与 REPL 共用同一条输入路径，前端可原样转发用户在底栏敲的内容（REQ-26）。
> M5 将引入显式 JSON 请求（`{"type":"eval",…}`、元命令、取消、订阅），届时裸文本保留为 `eval` 的简写。

## 响应（后端 → 前端）

```json
{"ok":true,"stack":["\"ab\""],"type":"result"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | 消息类型，M0 恒为 `"result"` |
| `ok` | bool | 是否成功 |
| `stack` | array[string] | 成功时：求值后剩余数据栈，**逐元素为 `%q` 渲染文本**（前端只负责显示，不再解析） |
| `code` | int | 失败时：REQ-23 分级的退出码 |
| `error` | string | 失败时：人类可读错误消息（中文） |

失败例：

```json
{"code":20,"error":"未知的词：nope","ok":false,"type":"result"}
```

**字段顺序**：实现按键名字符串序输出（`code` < `error` < `ok` < `stack` < `type`），
便于测试做逐字比对；JSON 对象本身无序，前端不得依赖顺序。

## 语义约定（M0）

1. **每个请求独立栈**（REQ-30）：并发/连续请求互不污染。
2. **字典全局**：前面请求中 `名字 : [ 体 ]` 定义的词，后续请求可用（D-06）。
3. **一次请求 = 一次求值**：请求内的多行需用 `\` 续行或未闭合块自动续行表达；
   换行即终结语句（REQ-04）。裸文本请求中若含换行，按多语句处理。
4. **流式**：M0 无流；REQ-08/REQ-36 的 `Stream`（fiber，chunk 到达即 flush）在 M5 以
   `{"type":"chunk",…}` / `{"type":"close",…}` 等消息引入，前端需支持**边收边渲染**。
5. **退出码**：单次求值失败**不**终止 `--serve` 循环，只反映在响应的 `code` 字段；
   进程退出码始终为 0（除非用法错误 2 或内部错误 50）。

## 与退出码的关系

`--serve` 的 `code` 字段与 CLI 退出码**同源**（`rb/exit-table`，REQ-23），
因此前端可以用同一套分级做提示（例如 10–19 词法、20–29 语法、30–39 运行时）。
